# Flashcard editor alternatives

Research date: 2026-10-27. This is a documentation and code review, not a prototype or benchmark.

## What Armin needs

The web editor stores Markdown, accepts image uploads, paste and drop, and supports image resizing. It resolves media references for display and converts them back on save. Math, GFM tables and HTML blocks currently fall back to source editing to avoid data loss; the read-only renderer supports KaTeX and other imported content. The editor also delays initialization to improve the card dialog's perceived speed. See `apps/web/src/components/ui/markdown-editor.tsx`, `markdown-image.ts`, and `docs/qa/2026-10-27-flashcard-editor-flash.md`.

The central design choice is whether Markdown remains the editable source of truth or is imported into a rich-text document and later serialized back. The latter requires the editor to represent every content construct it may encounter, including imported Anki content; a source view can offer an escape hatch but is not, by itself, a guarantee of preservation in rich mode.

## Common authoring patterns

- **Source and preview:** GitHub's file editor uses CodeMirror and a separate Preview tab; its comment composer likewise documents a Preview tab. Source stays visible while editing, with lower presentation complexity but more Markdown exposure. [GitHub file editor](https://docs.github.com/en/repositories/working-with-files/managing-files/editing-files), [GitHub writing guide](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/quickstart-for-writing-on-github).
- **Live or instant rendering:** Formatting appears inline while editing and syntax can be revealed around the caret; Vditor describes an instant-rendering mode alongside its other modes. This can make short cards readable without a second pane, but selection, editing around widgets and syntax discovery need evaluation. [Vditor README](https://github.com/Vanessa219/vditor/blob/master/README_en_US.md).
- **WYSIWYG:** Users edit rendered content, as in Milkdown's Crepe playground. It is approachable without Markdown knowledge but input is transformed into an editor representation, so unsupported imported constructs and fidelity need specific validation. [Crepe playground](https://milkdown.dev/playground).

These approaches are user experiences, not proof of the underlying storage or losslessness; for instance, instant rendering alone does not prove the original source is preserved.

## Candidates

- **MDXEditor** is an MIT-licensed React rich-text editor with Markdown input/output and plugins for tables, images and more. It has an upload callback and built-in paste/drop and resizing. It serializes resized images as HTML `img` tags, so Armin's existing image-size encoding and media reference contract would need an adapter and compatibility checks. Its docs explicitly warn of parse errors and missing plugins and offer source mode for recovery. This is the most promising off-the-shelf replacement if preserving rich editing is essential, but it still needs a corpus-based round-trip trial. [Project README](https://github.com/mdx-editor/editor/blob/main/README.md), [images](https://mdxeditor.dev/editor/docs/images), [error handling](https://mdxeditor.dev/editor/docs/error-handling), [source mode](https://mdxeditor.dev/editor/docs/diff-source).
- **Source editor plus preview** keeps the Markdown string as the document, avoiding automatic rich-text parse/serialize round trips. Armin already has a textarea and a matching renderer; a compact formatting toolbar and image insertion could improve usability without an editor framework. The UX tradeoff is exposed Markdown and a separate preview instead of in-place rich editing. [`@uiw/react-md-editor`](https://github.com/uiwjs/react-md-editor) is an MIT-licensed textarea-based React option with shortcuts, GFM, customizable preview, and toolbar controls; its default preview must be evaluated against Armin's own renderer and math/media behavior.
- **CodeMirror 6** represents the document as text and offers Markdown editing primitives and decorations that can replace or supplement displayed ranges with widgets. That creates a path to a live, source-preserving view, but polished inline image/math widgets, cursor behavior, mobile input, and resizing would be Armin's implementation work. It is a toolkit, not an out-of-the-box rich-text solution. [State reference](https://codemirror.net/docs/ref/), [decoration example](https://codemirror.net/examples/decoration/).
- **Milkdown / Crepe**: Milkdown is an MIT-licensed, plugin-driven WYSIWYG Markdown editor built on ProseMirror and remark. Crepe supplies a more complete editor with tables, inline and block KaTeX, image resizing, paste/drop and an upload callback. It therefore deserves a trial beside MDXEditor. Verify Armin's TeX delimiters, chemistry, image-size encoding and imported HTML rather than assuming feature labels imply compatibility. Sharing ProseMirror's document-model approach does not establish that serialization or initialization problems disappear. [Milkdown project](https://github.com/Milkdown/milkdown), [Crepe API](https://milkdown.dev/docs/api/crepe).
- **Vditor** is an MIT-licensed embeddable browser editor offering WYSIWYG, instant rendering and split view, with reported support for CommonMark, GFM and math. It is a candidate for trying a Typora-like card experience without implementing the complete interaction from CodeMirror primitives. Its broader syntax claims do not establish safe round-tripping of Armin's particular math, HTML, and image references; verify client-side assets, theming, small fields, accessibility, mobile and upload integration. [Vditor README](https://github.com/Vanessa219/vditor/blob/master/README_en_US.md).
- **BlockNote** is a polished block-editor option, but its documentation explicitly calls Markdown import and export lossy. It stores its own block format for lossless representation, making it a poor default for Armin's existing Markdown corpus unless the product adopts a different canonical format. [Format interoperability](https://www.blocknotejs.org/docs/foundations/supported-formats).
- **Novel** is a Notion-style editor built with TipTap, so it is not an independent alternative to the current engine. [Novel project](https://github.com/steven-tey/novel).

## Suggested decision process

Prototype a small front/back card form with Crepe or MDXEditor and compare it with the existing source textarea plus Armin's preview. Consider Vditor instant rendering if a single-surface Markdown experience is the priority. Use representative existing cards, especially imported tables, HTML, TeX and chemistry, code, media references, resized images, and mixed content. Verify open-and-save without edits and editing nearby text, plus image upload, paste, drop and resize. Compare semantic content and original source where preservation is required. Check empty and populated dialog first paint, keyboard focus and undo, paste, narrow mobile browser layouts, screen reader labels and production bundle size. A documentation review cannot establish that a replacement is faster, accessible, or lossless for this corpus.
