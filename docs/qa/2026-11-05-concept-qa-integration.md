# Concept integration QA (2026-11-05)

Local worktree deployment, desktop Chromium via agent-browser, sample account with complimentary Pro and the fake generator. No gateway model was configured.

- Created “Practice adding integers.” The deck displayed it as New and Concept, and its due count rose from three to four ([deck](2026-11-05-concept-qa-integration/deck.png)). Browse offered the Concept cards type filter and showed the card ([Browse](2026-11-05-concept-qa-integration/browse.png)).
- Reservation deletion regression: a temporary local internal mutation placed a 10-variant reservation on a concept card and a second 10-variant reservation in the same month. Deleting the card released its 10 immediately; invoking a late failure for the deleted job left the other 10 reserved. The temporary helper and artificial reservation were removed. Previously the deleted job alone released the reservation on reporting back; if it never reported, the reservation leaked, and a late result after a superseded or expired job could release another job's reservation. Card deletion now settles the current reservation, as do deck cleanup and reviewer reset; late results do nothing.

Validation: `pnpm check`, web build, and mobile bundle check passed for the deletion fix. The web build emitted a sourcemap warning.

- Archiving the concept card retained the Concept filter and added Archived; the due count fell from four to three. Unarchiving restored the due count ([archived](2026-11-05-concept-qa-integration/archived.png)). Card info opened with Schedule and Review history ([card info](2026-11-05-concept-qa-integration/card-info.png)); Stats and the graph opened without an error ([Stats](2026-11-05-concept-qa-integration/stats.png), [graph](2026-11-05-concept-qa-integration/graph.png)).
- Assistant tag-only edit: inspection found that `update_card` validated a supplied card body but skipped that validation when only tags were supplied, allowing an assistant to edit a concept card. The backend now rejects any `update_card` on a concept card. A temporary local internal wrapper called the same edit operation with the existing card and a tag-only request; it returned the expected INVALID error and was removed. This exercised the operation directly, without constructing an MCP grant or external client.
- Bounded deletion race: inspection showed a generation job could still store and charge variants after its deck was removed, before background cleanup removed the card; reviewer reset had the same window. The job lookup now requires an existing deck and active library. A temporary local mutation cloned the card, confirmed the job was current, then checked it was rejected both while the library was resetting and after the deck was removed. The helper and cloned rows were removed. This checks the boundary directly rather than timing a real asynchronous deletion.
- Cram setup matched four unlocked active units, including the concept card and excluding the locked sample card ([setup](2026-11-05-concept-qa-integration/cram.png)). A full cram session was not run in this walkthrough.
