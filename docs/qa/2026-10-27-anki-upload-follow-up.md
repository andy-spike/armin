# Anki upload follow-up — 2026-10-27

The worktree at `0fb1ad9d1051f9813bc1562b0ff05d55d1801b2b` was tested with the concurrent core conversion changes and the upload limit change described below, on its isolated local Convex deployment and headless Chromium. This is not a production test.

## Upload stall

A temporary Python HTTP probe (`/tmp/anki-upload-diagnosis/loop.py`) creates distinct small PNGs, sends authenticated uploads in batches, checks the web origin alongside each batch, requires HTTP 200 and an image reference, and exits nonzero on failure. Credentials stay in a private local browser state file and are not printed. With four uploads through `/media/upload`, batches 1–3 succeeded and batch 4 timed out after eight seconds. The simultaneous web check completed before that stall; immediately afterward both the web origin and Convex HTTP endpoint timed out at three seconds. Restarting `pnpm dev` restored them. This reproduces the reported local symptom, but remains intermittent and is not a fully minimized deterministic regression.

After restart, four concurrent uploads directly to the local Convex HTTP endpoint (bypassing the web proxy) completed one batch and timed out on the next; the web check also timed out. Later, after 80 sequential and 80 two-at-a-time direct uploads passed, another four-at-a-time direct batch timed out immediately. An additional 80 direct uploads at concurrency three passed. One startup attempt began before services were ready and is excluded. During a stalled direct run, a local Convex log recorded a disconnected JWKS request; this suggests a direction for investigation, but does not establish why the runtime stopped responding. The direct reproduction makes the web proxy alone an insufficient explanation. The backend, auth, runtime, and resource possibilities remain unresolved; no production impact is established.

The importer now limits image uploads to two concurrent requests as a conservative mitigation. With that limit, a generated APKG with 319 distinct PNGs previewed 319 basic cards and 319 images and completed in the browser with 319 cards in one deck. This is a synthetic stress test, not an original Geography import or proof that two concurrent requests can never stall. The synthetic deck was deleted through the UI and the sample deck still showed four cards. No automated suite was committed. Temporary proxy response buffering and debug logging left by the previous investigation were removed because their benefit was not established.

A separate generated three-note APKG previewed two basic cards and one cloze, with two images. It warned that additional cloze fields from one note were added to the answer. A temporary local-only backend hook rejected one specific image with HTTP 400 after preview; it was removed immediately afterward. The completed import reported two cards in one deck, one card left out because a required image could not be imported, and one image left out. Browse showed the surviving basic card and cloze. In the cloze editor, the optional extra retained its text and a labeled `Sketchy` section with its custom field, while the rejected image was absent. The required-image card did not appear in Browse. This tests a synthetic optional-extra loss and question-image loss; it does not cover every answer-image, omitted-field, or AnKing case. The probe deck was deleted and the four-card sample deck remained.
