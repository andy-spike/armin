## Concurrent uploads

The existing `/tmp/anki-upload-diagnosis/loop.py` sends small PNGs in four concurrent authenticated HTTP uploads and checks the web root alongside each batch. On the inherited deployment the first batch timed out twice (eight-second timeout), including after refreshing browser state. After restarting the worktree services, the first batch again timed out; the web root and Convex API version endpoint responded, while the HTTP-action endpoint timed out. After another restart, a fresh browser login, and the successful original Geography and Physics imports above, the probe completed five batches (20 uploads), then all four uploads in batch six timed out; the web root returned 200. Thus the current configuration did not eliminate the intermittent local stall. The probe itself is distinct from the import and does not establish production impact or a root cause. Prior static-JWKS comparison evidence is in the interrupted investigation; these failures prevent treating that change as verified. A new synthetic 319-image import was not run because the original Geography import covered 319 images; the earlier synthetic run used a different upload concurrency setting.
