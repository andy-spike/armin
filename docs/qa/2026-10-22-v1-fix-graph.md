# QA fix walkthrough: prerequisite graph (v1)

Date: 2026-10-22
Area: `/deck/<id>/graph`, graph canvas editing, and prerequisite links
Branch: `t3/fix-prerequisite-graph-qa`
Environment: isolated T3 worktree, `http://armin-b7044a391d.localhost:16744`, local Convex deployment, sample account `test@example.com`.
Browser: agent-browser managed Chromium, session `graphfix-52eef440225c`. Viewport widths are emulated desktop browser sizes (1280×577, 1440×900, 390×844), not real devices.

## Issues

### 1. Blocker: delete before confirmation

**Root cause:** the node context menu called
`onDeleteCardRequest?.(menu.nodeId) ?? deleteNode(menu.nodeId)`. The callback returns
`undefined`, so `??` always evaluated the fallback, which removed the node locally
and called `onGraphChange`. That deleted the card on the server and fired
`removePrereq` for its edges, producing the spurious "Couldn't remove link" toast.

**Change:** the menu item now calls `onDeleteCardRequest` when it exists and only
falls back to `deleteNode` when the graph has no request handler. The existing
Delete/Backspace guard (`onBeforeDelete` returns no nodes) was re-checked.

**Verification:** opened the node menu, chose **Delete flashcard**, and confirmed the
card and edge were still present behind the dialog
(`screenshots/graph-delete-dialog-card-present.png`). **Cancel** kept the card and
edge. Confirming deleted the card once, left one "Flashcard deleted" toast, and
produced no "Couldn't remove link" toast (`screenshots/graph-delete-toast.png`).
Selecting a card and pressing Delete left all four cards on the canvas.

### 2. Major: search could not reveal off-screen matches

**Root cause:** search only computed match emphasis; it never changed the viewport.
React Flow virtualizes nodes, so an off-screen match was not even mounted.

**Change:** matches are computed once and reused for emphasis and navigation.
When the query settles (300 ms) or Enter is pressed, `fitView` frames the matching
nodes. The toolbar shows "N matches · Enter to jump" or
"No cards match “query”.".

**Verification:** panned a 150% graph so the match was off-screen
(`screenshots/graph-search-before.png`). Typing "Knowledge to learn" moved the
viewport (`translate(472px, 384.5px) scale(1)`), rendered the matching card, dimmed
the rest, and showed "1 match · Enter to jump"
(`screenshots/graph-search-after.png`). A query with no matches showed
"No cards match “zzzz”." and the dimmed canvas at 390 px
(`screenshots/graph-search-no-results-390.png`).

### 3. Major: deleted/malformed deck graph opened an empty editable graph

**Root cause:** `armin.graph.getDeck` maps a missing deck to an empty graph, and the
route never checked the deck query for a missing deck, so it rendered the normal
"No flashcards yet" state with a working Add-card entry point.

**Change:** the graph route now renders the same "Deck not found" empty state as the
deck detail route when the deck query succeeds with no deck. The graph query is
disabled until the deck exists, and the loader resolves the deck before prefetching
the graph, so an unknown id never looks like an empty deck.

**Verification:** `/deck/abc123/graph`, `/deck/%00/graph`, a deleted deck's graph URL,
and a valid-shaped but nonexistent id all showed "Deck not found" with no
"Add your first card" button and no console or Convex validation errors
(`screenshots/graph-not-found.png`).

### 4. Major: graph authoring was pointer-only

**Root cause:** nodes had no visible focus styling and no key handling, edges were
not focusable, and links could only be created by dragging handles.

**Change:**
- Focused cards get a 2 px accent outline (`graph.css`).
- Enter on a focused card opens its editor.
- Shift+F10 and the Context Menu key open the card menu at the card.
- The card menu gained **Add prerequisite…**, **Add dependent…**, and
  **Remove prerequisite…** (the last appears when the card has prerequisites).
  They open a searchable card picker in a modal. Candidates are filtered with the
  same self-loop, duplicate, and cycle rules, and every pick runs through the same
  validation as a drag.
- The menu focuses its first item, supports Up/Down and Escape, and restores focus.
- The toolbar moved before the canvas in DOM order, so Search and Tidy come before
  the cards in tab order. Delete-dialog Cancel also receives initial focus.

**Verification:** Shift+F10 opened the menu with "Edit flashcard" focused
(`screenshots/graph-keyboard-menu.png`); arrow keys and Enter opened the picker
(`screenshots/graph-link-picker.png`). Picking a card created the edge and locked
the dependent; **Remove prerequisite…** removed it; Enter on a focused card opened
the prefilled editor; Escape returned focus to the card. Computed focus styling was
`solid 2px rgb(36, 131, 123)` with a 2 px offset. At 390 px the toolbar controls did
not overlap and the page had no horizontal scroll.

### 5. Minor: rejected links gave no feedback

**Root cause:** `isValidConnection` rejected the drop before `onConnect`, and
`onConnectEnd` returned early for any drop on a node, so no explanation surfaced.

**Change:** `onConnectEnd` now distinguishes a rejected drop on a card and reports
the specific reason. All link creation paths share one `addLink` validation helper.
Duplicate attempts get a new "Those flashcards are already linked." message.

**Verification:** dragging Beta → Alpha on an A → B link showed
"That link would create a cycle."; re-dragging an existing link showed
"Those flashcards are already linked."; dragging a card onto itself showed
"A flashcard can’t depend on itself." Each attempt left the edge count unchanged.

### 6. Minor: archived cards looked active

**Root cause:** the backend returned `archived`, but the web graph view model and
node data dropped it.

**Change:** `archived` now flows through `UiGraphNode`, flow-node data, and the update
comparison. Archived nodes show the same neutral Archived badge as deck tiles.

**Verification:** archived a card on the deck page, opened the graph, and confirmed
the node showed "Archived" next to its state badge
(`screenshots/graph-archived.png`); unarchived it afterwards.

### 7. Minor: Fit view could not frame large graphs

**Root cause:** the 25% minimum zoom clamped Fit view, and there was no overview.

**Change:** minimum zoom is 10%, and the canvas has a pannable/zoomable MiniMap
(hidden below the `md` breakpoint to keep narrow screens clear).

**Verification:** the zoom field accepted 10% and stopped there; Fit view rendered
all four sample cards and the MiniMap was visible and interactive
(`screenshots/graph-archived.png`).

### 8. Minor: graph page had no h1

**Change:** added an `sr-only` h1 naming the deck ("<deck> prerequisite graph"), plus
an h1 in the not-found state.

**Verification:** the accessibility tree reports
`heading "Agent sample library prerequisite graph" [level=1]` and
`heading "Deck not found" [level=1]`.

### 9. Cosmetic: "Flashcard deleted" used error styling

**Root cause:** the graph delete mutation used `tone: "error"` for success.

**Change:** `tone: "success"`.

**Verification:** the toast renders the green check icon and success colour
(`screenshots/graph-delete-toast.png`).
