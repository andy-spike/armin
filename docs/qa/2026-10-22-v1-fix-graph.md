# QA fix walkthrough: prerequisite graph (v1)

Date: 2026-10-22
Area: `/deck/<id>/graph`, graph canvas editing, and prerequisite links
Branch: `t3/fix-prerequisite-graph-qa`
Environment: isolated T3 worktree, `http://armin-b7044a391d.localhost:16744`, local Convex deployment, sample account `test@example.com`.
Browser: agent-browser managed Chromium, session `graphfix-52eef440225c`. Viewport widths are emulated desktop browser sizes (1280×577, 1440×900, 390×844), not real devices.

## Issues

### 1. Blocker: delete before confirmation

**Root cause:** the node context menu called
`onDeleteCardRequest?.(menu.nodeId) ?? deleteNode(menu.nodeId)`. The callback returns
`undefined`, so `??` always evaluated the fallback, which removed the node locally
and called `onGraphChange`. That deleted the card on the server and fired
`removePrereq` for its edges, producing the spurious "Couldn't remove link" toast.

**Change:** the menu item now calls `onDeleteCardRequest` when it exists and only
falls back to `deleteNode` when the graph has no request handler. The existing
Delete/Backspace guard (`onBeforeDelete` returns no nodes) was re-checked.

**Verification:** opened the node menu, chose **Delete flashcard**, and confirmed the
card and edge were still present behind the dialog
(`screenshots/graph-delete-dialog-card-present.png`). **Cancel** kept the card and
edge. Confirming deleted the card once, left one "Flashcard deleted" toast, and
produced no "Couldn't remove link" toast (`screenshots/graph-delete-toast.png`).
Selecting a card and pressing Delete left all four cards on the canvas.

### 2. Major: search could not reveal off-screen matches

**Root cause:** search only computed match emphasis; it never changed the viewport.
React Flow virtualizes nodes, so an off-screen match was not even mounted.

**Change:** matches are computed once and reused for emphasis and navigation.
When the query settles (300 ms) or Enter is pressed, `fitView` frames the matching
nodes. The toolbar shows "N matches · Enter to jump" or
"No cards match “query”.".

**Verification:** panned a 150% graph so the match was off-screen
(`screenshots/graph-search-before.png`). Typing "Knowledge to learn" moved the
viewport (`translate(472px, 384.5px) scale(1)`), rendered the matching card, dimmed
the rest, and showed "1 match · Enter to jump"
(`screenshots/graph-search-after.png`). A query with no matches showed
"No cards match “zzzz”." and the dimmed canvas at 390 px
(`screenshots/graph-search-no-results-390.png`).

### 3. Major: deleted/malformed deck graph opened an empty editable graph

**Root cause:** `armin.graph.getDeck` maps a missing deck to an empty graph, and the
route never checked the deck query for a missing deck, so it rendered the normal
"No flashcards yet" state with a working Add-card entry point.

**Change:** the graph route now renders the same "Deck not found" empty state as the
deck detail route when the deck query succeeds with no deck. The graph query is
disabled until the deck exists, and the loader resolves the deck before prefetching
the graph, so an unknown id never looks like an empty deck.

**Verification:** `/deck/abc123/graph`, `/deck/%00/graph`, a deleted deck's graph URL,
and a valid-shaped but nonexistent id all showed "Deck not found" with no
"Add your first card" button and no console or Convex validation errors
(`screenshots/graph-not-found.png`).

### 4. Major: graph authoring was pointer-only

**Root cause:** nodes had no visible focus styling and no key handling, edges were
not focusable, and links could only be created by dragging handles.

**Change:**
- Focused cards get a 2 px accent outline (`graph.css`).
- Enter on a focused card opens its editor.
- Shift+F10 and the Context Menu key open the card menu at the card.
- The card menu gained **Add prerequisite…**, **Add dependent…**, and
  **Remove prerequisite…** (the last appears when the card has prerequisites).
  They open a searchable card picker in a modal. Candidates are filtered with the
  same self-loop, duplicate, and cycle rules, and every pick runs through the same
  validation as a drag.
- The menu focuses its first item, supports Up/Down and Escape, and restores focus.
- The toolbar moved before the canvas in DOM order, so Search and Tidy come before
  the cards in tab order. Delete-dialog Cancel also receives initial focus.

**Verification:** Shift+F10 opened the menu with "Edit flashcard" focused
(`screenshots/graph-keyboard-menu.png`); arrow keys and Enter opened the picker
(`screenshots/graph-link-picker.png`). Picking a card created the edge and locked
the dependent; **Remove prerequisite…** removed it; Enter on a focused card opened
the prefilled editor; Escape returned focus to the card. Computed focus styling was
`solid 2px rgb(36, 131, 123)` with a 2 px offset. At 390 px the toolbar controls did
not overlap and the page had no horizontal scroll.

### 5. Minor: rejected links gave no feedback

**Root cause:** `isValidConnection` rejected the drop before `onConnect`, and
`onConnectEnd` returned early for any drop on a node, so no explanation surfaced.

**Change:** `onConnectEnd` now distinguishes a rejected drop on a card and reports
the specific reason. All link creation paths share one `addLink` validation helper.
Duplicate attempts get a new "Those flashcards are already linked." message.

**Verification:** dragging Beta → Alpha on an A → B link showed
"That link would create a cycle."; re-dragging an existing link showed
"Those flashcards are already linked."; dragging a card onto itself showed
"A flashcard can’t depend on itself." Each attempt left the edge count unchanged.

### 6. Minor: archived cards looked active

**Root cause:** the backend returned `archived`, but the web graph view model and
node data dropped it.

**Change:** `archived` now flows through `UiGraphNode`, flow-node data, and the update
comparison. Archived nodes show the same neutral Archived badge as deck tiles.

**Verification:** archived a card on the deck page, opened the graph, and confirmed
the node showed "Archived" next to its state badge
(`screenshots/graph-archived.png`); unarchived it afterwards.

### 7. Minor: Fit view could not frame large graphs

**Root cause:** the 25% minimum zoom clamped Fit view, and there was no overview.

**Change:** minimum zoom is 10%, and the canvas has a pannable/zoomable MiniMap
(hidden below the `md` breakpoint to keep narrow screens clear).

**Verification:** the zoom field accepted 10% and stopped there; Fit view rendered
all four sample cards and the MiniMap was visible and interactive
(`screenshots/graph-archived.png`).

### 8. Minor: graph page had no h1

**Change:** added an `sr-only` h1 naming the deck ("<deck> prerequisite graph"), plus
an h1 in the not-found state.

**Verification:** the accessibility tree reports
`heading "Agent sample library prerequisite graph" [level=1]` and
`heading "Deck not found" [level=1]`.

### 9. Cosmetic: "Flashcard deleted" used error styling

**Root cause:** the graph delete mutation used `tone: "error"` for success.

**Change:** `tone: "success"`.

**Verification:** the toast renders the green check icon and success colour
(`screenshots/graph-delete-toast.png`).

## Round 2 — follow-up verification findings

Date: 2026-10-22
Branch: `t3/graph-qa-round-2-fixes`
Environment: same worktree, web `http://armin-cce8eea3e4.localhost:25896`, local
Convex deployment, sample account `test@example.com`. Browser: agent-browser
managed Chromium, session `graphr2-aafa690070f8`, viewport 1280 × 800 (emulated
desktop browser size, not a real device).

Fixtures were created through the app/backend API with a throwaway operator
script outside the repository (deleted afterwards): `QA R2 delete` (5 cards,
4 links), `QA R2 search` (11 cards, 10 containing “Match card”), and two decks
both named `QA R2 duplicate`. Each issue was reproduced on the unmodified code
before the fix, then rechecked in the same running app.

### 1. HIGH — Delete/Backspace on a selected card removed every incident link

**Root cause:** `onBeforeDelete` returned the entire edge candidate set React
Flow supplied. React Flow adds every edge connected to a selected node to that
set (and `nodes: []` suppressed the card), so a selected card's incident links
were deleted as if the user had selected the links themselves.

**Change:** `onBeforeDelete` now returns no nodes and only candidate edges whose
own `selected` flag is set. A selected card with Delete or Backspace is a no-op;
card deletion stays in the confirmation dialog.

**Verification:**

- Before: selecting the hub on the 5-card / 4-link deck and pressing Delete left
  5 cards but 0 links; the loss persisted after reload
  (`screenshots/r2-prefix-delete-before.png`,
  `screenshots/r2-prefix-delete-after.png`).
- After: Delete and Backspace with the hub selected kept 5 cards / 4 links, also
  after reload (`screenshots/r2-card-delete-key-guarded.png`).
- An explicitly clicked edge selected alone: Delete removed exactly that edge
  (4 → 3 links, 5 cards unchanged) (`screenshots/r2-edge-delete-key.png`).
- Ctrl-clicking an edge with a card already selected: Delete removed only the
  selected edge (4 → 3 links, 5 cards unchanged)
  (`screenshots/r2-card-edge-multiselect-delete.png`).

### 2. MEDIUM — every edge was an invisible tab stop

**Root cause:** React Flow's `edgesFocusable` default is true, so all edges had
`tabindex="0"` and the graph had no focus style for them.

**Change:** `edgesFocusable={false}` on the canvas. Links stay removable by
clicking an edge or through the card menu's **Remove prerequisite…** picker.

**Verification:** before, tabbing from Tidy visited 4 edges before the first
card and a focused edge computed `outline: none`
(`screenshots/r2-prefix-edge-tabstop.png`). After, the edges have no `tabindex`
attribute, Tab from Tidy lands directly on the first card with a
`solid 2px rgb(28, 108, 102)` focus ring
(`screenshots/r2-card-first-tab-stop.png`).

### 3. LOW — Enter framed all search matches instead of stepping through them

**Root cause:** the Enter handler always called `fitView` with the complete match
set; there was no current-match cursor or position display.

**Change:** matches are kept in deck order. Enter advances to the next match and
centers it, Shift+Enter moves to the previous one, and both wrap. The current
match gets the active card emphasis, and the status shows `2 of 10 · Enter for
next`. The debounced reveal still frames all matches first; stepping sets the
revealed-query marker so the debounce does not re-frame the set afterwards.

**Verification:** searching `Match card` showed `10 matches · Enter to step
through` and framed all 10. Pressing Enter showed `1 of 10` at 100% zoom with
Match card 01 highlighted (`screenshots/r2-search-step-1.png`); the next Enter
showed `2 of 10` with card 02 highlighted
(`screenshots/r2-search-step-2.png`); Shift+Enter returned to `1 of 10`, and
Shift+Enter at the first match wrapped to `10 of 10`
(`screenshots/r2-search-step-wrap.png`). A single-match query showed `1 of 1`,
and clearing the query removed the position. The no-match text still reads
`No cards match “zzzz”.`

### 4. LOW — dropping a link drag on a card body opened the add-card popup

**Root cause:** `onConnectEnd` only treated `connectionState.toNode` as a link
attempt. React Flow reports that only for handle targets, so a body release fell
through to the empty-pane branch.

**Change:** when `toNode` is absent, resolve the `.react-flow__node` under the
pointer with `elementFromPoint`, and send a hit card through the shared `addLink`
validation. Rejected body drops get the same self-loop, duplicate, and cycle
toasts as handle drops; only a true pane release still opens **Add connected
flashcard**.

**Verification:** before, dragging from a handle to a card body opened the
`Add connected flashcard` menu with no edge change
(`screenshots/r2-prefix-body-drop-menu.png`). After, dropping on a card body
created the link (4 → 5 links, no menu) and it survived reload
(`screenshots/r2-body-drop-creates-link.png`). A duplicate body drop showed
`Those flashcards are already linked.` with the count unchanged
(`screenshots/r2-body-drop-duplicate-toast.png`); cycle and self-loop body drops
showed their messages and left the count unchanged
(`screenshots/r2-invalid-body-drops.png`). Dropping on empty canvas still opened
the add-card menu.

### 5. LOW — move picker showed duplicate deck names identically

**Root cause:** `MoveFlashcardDialog` rendered `deck.name` directly, unlike
Browse's numbered duplicate handling.

**Change:** it now imports `buildDeckFilterOptions` from `@/lib/browse`, drops
the `All decks` entry, and uses the same numbered labels for the trigger and
options.

**Verification:** before, the picker listed `QA R2 duplicate` twice
(`screenshots/r2-prefix-move-duplicates.png`). After, it lists
`1 · QA R2 duplicate` and `2 · QA R2 duplicate` in the same name order as Browse
(`screenshots/r2-move-duplicates-numbered.png`).

### 6. LOW — delete confirmation focused the dialog panel, not Cancel

**Root cause:** `Dialog` focuses its panel when it contains no contenteditable,
input, or select, and that frame ran after the Cancel button's `autoFocus`.
`apps/web/src/components/ui/dialog.tsx` has no initial-focus-button API and is
outside this task's file scope.

**Change:** the ineffective `autoFocus` was removed; the Cancel button now has a
ref and receives focus on the second animation frame after the dialog's own
panel-focus frame. No change to `dialog.tsx`.

**Verification:** before, `document.activeElement` after choosing **Delete
flashcard** was the `[role="dialog"]` panel
(`screenshots/r2-prefix-delete-focus.png`). After, it is the Cancel button
(`screenshots/r2-delete-dialog-cancel-focus.png`), and activating it (or Escape)
keeps the card and links.

### Round-1 regression checks

- **Delete confirmation:** opening **Delete flashcard** from the card context
  menu and choosing Cancel kept 5 cards / 5 links after reload. Confirming on a
  later run deleted the hub exactly once (5 → 4 cards, 5 → 1 link), showed one
  `Flashcard deleted` success toast, no `Couldn't remove link` text, and the
  deletion survived reload (`screenshots/r2-delete-confirm-toast.png`).
- **Keyboard pickers:** Shift+F10 opened the card menu; arrow navigation reached
  **Remove prerequisite…**, whose picker removed the only hub → dependent A link
  (5 → 4 links). **Add prerequisite…** re-added it through the picker
  (4 → 5 links).
- **Invalid-link toasts:** self-loop, duplicate, and cycle drags still report
  the specific reason and leave the edge count unchanged.
- **Search reveal:** the debounce still frames all matches, the no-match message
  is unchanged, and edges are out of the tab order before cards.
