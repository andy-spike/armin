Armin's hosted MCP server lets your assistant create study cards, link prerequisites, and manage your library. Your assistant reads the material you provide and writes the cards; Armin stores them and schedules your reviews.

You need an [Armin account](https://armincards.app/sign-up) with a verified email and an assistant that supports remote MCP servers with OAuth. Your assistant provider's plan and workspace restrictions apply. Nothing needs to run on your computer for the hosted connection.

## Server details

**MCP server URL:**

`https://intent-bullfrog-922.convex.site/mcp`

- **Transport:** Streamable HTTP over HTTPS.
- **Authentication:** OAuth authorization code flow with S256 PKCE and dynamic client registration. Choose OAuth in your client; no personal API key or manually supplied client secret is needed.
- **Authorization scopes:** `armin:read`, `armin:write`, `armin:import`, and `armin:study`. A client that asks for no scope receives all four. Each connection only sees and can use tools in the groups you approved.

The server URL is an integration endpoint, not a webpage. Opening it directly in a browser is not a connection test.

Signed in to Armin, choose **AI setup** in the sidebar for these steps with copy buttons, plus a prompt you can paste into Claude Code or Codex so the agent sets up the connection itself.

## Connect Claude

While the public directory listing is pending, use a custom connector:

1. In Claude, open **Customize → Connectors → Add custom connector**.
2. Name it **Armin** and paste the MCP server URL above.
3. Add the connector, choose **Connect**, and sign in to Armin in the page that opens.
4. Review the requested access and approve the connection.
5. Enable Armin in your conversation and ask it to create or read a deck.

In a managed workspace, an owner may need to add or allow the connector first. Once Armin is listed in your provider's directory, you can install the listing instead of entering the URL. Both paths use the same server and access model.

[Claude's custom connector guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

## Connect ChatGPT

1. Open [ChatGPT Plugins](https://chatgpt.com/plugins).
2. Choose **+ → Add custom MCP server**, name it **Armin**, and enter the MCP server URL.
3. Choose **OAuth**, review the warning, and select **Create as a plugin**.
4. Sign in to Armin and approve the connection.
5. Start a conversation, type **@**, select Armin, and send your request.

Account and workspace policies control whether custom servers are available. If a client asks for a client ID or secret, use automatic registration when offered; Armin does not supply a shared client secret.

[OpenAI's connection guide](https://developers.openai.com/plugins/deploy/connect-chatgpt)

## Connect Gemini

Gemini calls MCP servers "custom apps". You need a personal Google Account (not work or school), to be 18 or older in the US, Gemini in English, and Keep Activity turned on.

1. On a computer, open [gemini.google.com](https://gemini.google.com).
2. Open **Settings → Connected Apps** (if it's missing, choose **Personal Intelligence** first).
3. Under **Custom apps**, choose **Add a custom app**.
4. Paste the MCP server URL above and choose **Next**. Skip **Advanced features**; Armin registers Gemini automatically.
5. Sign in to Armin and approve the connection.

Custom apps added on the web also work in the Gemini mobile app.

[Google's custom apps guide](https://support.google.com/gemini/answer/17209137)

## Connect coding agents

For Claude Code, run:

```sh
claude mcp add --transport http armin https://intent-bullfrog-922.convex.site/mcp
```

Then run `/mcp` in Claude Code, select **armin**, and authenticate. The command applies to the current project by default; add `--scope user` to make the connection available across projects.

For Codex, run:

```sh
codex mcp add armin --url https://intent-bullfrog-922.convex.site/mcp
codex mcp login armin
```

Approve the connection in the Armin page that opens. Use a current client version that supports remote MCP and OAuth.

## Choose what your assistant can access

Every new connection asks for your approval and lists the permissions it
requested. There are four permission groups, and each covers your whole library,
including every existing deck and any decks and cards you add later:

- **Read** (`armin:read`): find and read decks, cards, prerequisite links, study
  stats, and card details, and read the authoring and Anki guides.
- **Write** (`armin:write`): create and edit cards and decks, archive cards, move
  cards, and change prerequisite links.
- **Import** (`armin:import`): convert and stage Anki files, upload their images,
  and publish the new decks after you approve the preview.
- **Study** (`armin:study`): show the cards that are due and record your own
  ratings.

There are no per-deck choices. A client that asks for no scope receives all four.
A connection approved before these groups existed has the old `armin:author`
scope; it cannot call tools and is marked as needing reconnection in Settings.
Reconnect it from the assistant to approve the new groups.

Armin limits the tools themselves. The assistant cannot permanently delete cards
or decks, reschedule cards on its own, upload images outside an approved Anki
import, export your library, or manage your account. Ratings are recorded only
when you give them, one card at a time.

Client names are supplied by the connecting app and are not verified by Armin. Check the client name and callback origin on the consent screen before approving.

## Manage or disconnect an assistant

Open [Armin Settings](https://armincards.app/settings) and select **AI assistants** to:

- See connected assistants and what they can access.
- Inspect recent activity summaries to see which assistant changed which deck.
- Disconnect a connection. Its access to Armin stops immediately; your decks and cards remain.

You can also remove the connector or plugin in the assistant's own settings. Disconnect it in Armin when you want to ensure its server access has ended. Reconnecting requires a new approval.

- “Make an Armin deck from these lecture notes, with prerequisites.”
- “Which Armin decks can you see?”
- “Find the card about photosynthesis and fix its answer.”
- “Show me the cards in this deck and how they depend on each other.”
- “Update this card's answer to include the example below.”
- “Archive this card.”
- “How is my Armin retention and which decks are weakest?”
- “Quiz me on my due cards one at a time.”
- “Here is my answer—rate that card Good.”

Open the returned deck link to inspect the result and study in Armin. Review generated cards for accuracy before relying on them.

## Available tools

There are twenty tools across the four permission groups.

### Read (`armin:read`)

| Tool                 | What it does                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `list_decks`         | Lists the decks in your library, 200 per page, with card counts and how many cards are due now.                                |
| `search_cards`       | Finds cards by text, deck, or tag and returns their IDs, versions, and deck links.                                             |
| `read_deck`          | Reads a deck's cards in pages, with full content or compact previews, plus its prerequisite links and revision.                |
| `get_study_overview` | Summarizes due now, scheduled reviews due today, new cards available, streak, 30-day retention, and the five weakest decks.    |
| `get_card_details`   | Shows one card's full content and each review unit's state, due time, stability, difficulty, reps, lapses, and recent reviews. |
| `get_guide`          | Returns Armin's card-writing guidance or the Anki converter kit, limits, and import workflow.                                  |
| `anki_import_status` | Reads a staged Anki import's progress, counts, unresolved notes, and final deck links.                                         |

### Write (`armin:write`)

| Tool                | What it does                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| `save_cards`        | Saves 1–50 text cards and up to 100 prerequisite links in one atomic batch, in a new or existing deck.   |
| `update_card`       | Edits one card, checking its version and preserving existing review items.                               |
| `set_card_archived` | Archives or unarchives one card without deleting its review history.                                     |
| `update_deck`       | Changes a deck's name or description.                                                                    |
| `set_prerequisite`  | Adds or removes a same-deck prerequisite link, rejecting cycles.                                         |
| `move_card`         | Moves a card between decks while preserving study state; refuses to silently discard prerequisite links. |

### Import (`armin:import`)

| Tool                       | What it does                                                                            |
| -------------------------- | --------------------------------------------------------------------------------------- |
| `anki_import_start`        | Starts a staged import from the converter plan and returns a scoped image upload token. |
| `anki_import_add_batch`    | Stages up to 100 cards and 1,500 review items, with explicit skip reasons.              |
| `anki_import_upload_token` | Issues a fresh scoped upload token if the first was lost.                               |
| `anki_import_finalize`     | Publishes a complete, user-approved import after checking its preview checksum.         |
| `anki_import_cancel`       | Cancels an import and removes its staged cards, decks, and unshared uploads.            |

### Study (`armin:study`)

| Tool            | What it does                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `get_due_cards` | Returns the next due review units in the app's queue order, with prompts and a state token. Answers are separate and must not be revealed early. |
| `rate_card`     | Records the user's own rating for one review unit. The assistant must never choose the rating, and stale state tokens are rejected.              |

Supported card types are basic, reversed, cloze, and typed-answer. Call `get_guide` with topic `authoring` before writing cards; it returns Armin's card-writing rules, from learning goals and card types to prerequisite links. The assistant cannot permanently delete cards or decks, reschedule cards on its own, upload images outside an approved Anki import, export your library, or administer your account. Edits that would remove existing review items or change image content must be performed in Armin.

Each connection can make up to 60 writes per hour on Free (600 on Pro) and 2,000 reads per hour on Free (6,000 on Pro). Ratings count as writes. An account can have up to 20 active connections. Normal library quotas also apply. Large card sets need multiple batches; each batch succeeds or fails as a unit. Stale edits are rejected instead of overwriting a newer change.

## Troubleshooting

**The assistant cannot see a deck.** Confirm you signed into the intended Armin account and that the connection is still listed under **Settings → AI assistants**. An approved connection can use every deck in the active library, subject to its permission groups; there is no per-deck sharing step. If it only has the read group, editing tools stay hidden.

**The assistant shows no Armin tools or reports missing permissions.** The connection may have been approved with the old single `armin:author` scope. Reconnect it from the assistant and approve the current permission groups. Settings marks it as needing reconnection until you do.

**Sign-in or approval expired.** Start the connection again from your assistant. Consent requests expire after ten minutes. If a previously working connection reports an authentication error, reconnect and approve it again.

**A write is refused.** Check that the connection is still approved. For a version conflict, ask the assistant to read the latest card or graph and retry. A quota error may require waiting for the hourly limit or reducing the batch size. If a tool rejects its input, the error names the field and the rule that failed, such as a length limit or allowed format; ask the assistant to correct that argument.

**The custom connector option is missing.** Check your provider's plan and workspace policy with its administrator. Armin cannot enable a feature blocked by the provider.

**The server cannot be reached.** Use the exact HTTPS URL, including `/mcp`. Hosted chat apps cannot reach a local development server. For persistent failures, [open a support issue](https://github.com/andy-spike/armin/issues) with the client name, time, and error message. Do not include passwords, authorization codes, access tokens, or private card content.

## Data and privacy

Armin stores authorized card content, deck information, prerequisite links, and connection records. It does not fetch the source pages you share or run an AI model on your behalf. Your assistant provider handles the conversation under its own policies.

Connection activity summaries are retained for 90 days and do not contain card snapshots or source documents. Disconnecting an assistant does not delete its saved study content. See the [Privacy Policy](https://armincards.app/privacy) and [Terms of Service](https://armincards.app/terms) for the full data and account rules.

## Public test account

For evaluation, use `reviewer@armincards.app` with password `ArminDemo123!` at [Armin sign-in](https://armincards.app/sign-in). This is a shared, disposable account: everyone using it can see and change its library. Do not add private material.

Its data is restored to a sample deck roughly every six hours, with up to five minutes of scheduling delay. Sign-in sessions and OAuth connections remain, but links to deleted cards and decks become invalid. Approved connections keep their whole-library access across the reset. The account's credentials and deletion are protected so it remains available to testers.

For permanent study content and private data, create your own account.

## Anki imports

Call `get_guide` with topic `anki_import` for the maintained converter kit and staged import
protocol. Your assistant needs attachment/file access and Node.js execution.
Conversion runs in the assistant workspace, with supported images preserved.
Resolve unsupported cards by requested repair or explicit skip, review the final
preview from `anki_import_status` with `includePreview: true`, and approve before
publishing new decks. MCP imports start fresh; browser import can preserve study
progress. See [the import guide](https://github.com/andy-spike/armin/blob/master/docs/anki-assistant-import.md).
